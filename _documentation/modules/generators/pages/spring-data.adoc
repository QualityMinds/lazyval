= Spring Data

This generator produces a single `@Configuration` class that contains all read/write converters for your
domain-primitives as private nested types, and registers them with the detected Spring Data store's
`CustomConversions` bean.
It activates whenever `spring-data-commons` is on the classpath, which is always the case when any Spring
Data store module is present.

The `CustomConversions` registration is store-specific. When both stores are present, the generated
class contains one bean method per store:

* `CassandraCustomConversions` — when `spring-data-cassandra` is on the classpath
* `MongoCustomConversions` — when `spring-data-mongodb` is on the classpath

== Config Options

|===
|Property |Description

|_lazyval.spring_data.package_
|Specifies the package where the configuration class is generated.
Overrides `lazyval.generators.basePackage`.

|_lazyval.spring_data.cassandra.converters_
|Comma-separated list of fully qualified `Converter` class names appended to the
`CassandraCustomConversions` registration. See <<user-supplied-converters>>.

|_lazyval.spring_data.mongo.converters_
|Comma-separated list of fully qualified `Converter` class names appended to the
`MongoCustomConversions` registration. See <<user-supplied-converters>>.

|===

== Generated Files

A single `LazyvalSpringDataConfiguration` class is generated.
All read/write converters are contained within it as private, final types — they are plain objects
instantiated with `new`, not Spring beans, and are not visible outside the generated file.

[tabs]
====
Java::
+
[source,java]
----
/**
 * Generated Spring Data converter configuration.
 *
 * Registers all read/write converters for types annotated with {@code @Lazyval}
 * with the appropriate Spring Data store-specific conversion service.
 *
 * Generated by the Lazyval annotation processor. Do not modify.
 */
@Configuration
public class LazyvalSpringDataConfiguration {

    @Bean
    @ConditionalOnMissingBean
    public CassandraCustomConversions cassandraCustomConversions() {
        List<Converter<?, ?>> converters = List.of(
            new IsbnReadConverter(),
            new IsbnWriteConverter(),
            new QuantityReadConverter(),
            new QuantityWriteConverter()
        );
        return new CassandraCustomConversions(converters);
    }

    @Bean
    @ConditionalOnMissingBean
    public MongoCustomConversions mongoCustomConversions() {
        List<Converter<?, ?>> converters = List.of(
            new IsbnReadConverter(),
            new IsbnWriteConverter(),
            new QuantityReadConverter(),
            new QuantityWriteConverter()
        );
        return new MongoCustomConversions(converters);
    }

    @ReadingConverter
    private static final class IsbnReadConverter implements Converter<String, Isbn> {
        @Override
        public Isbn convert(String source) {
            return Isbn.parse(source);
        }
    }

    @WritingConverter
    private static final class IsbnWriteConverter implements Converter<Isbn, String> {
        @Override
        public String convert(Isbn source) {
            return source.value();
        }
    }

    // ... one pair per domain-primitive
}
----

Kotlin::
+
[source,kotlin]
----
/**
 * Generated Spring Data converter configuration.
 *
 * Registers all read/write converters for types annotated with `@Lazyval`
 * with the appropriate Spring Data store-specific conversion service.
 *
 * Generated by the Lazyval annotation processor. Do not modify.
 */
@Configuration
class LazyvalSpringDataConfiguration {

    @Bean
    @ConditionalOnMissingBean
    fun cassandraCustomConversions(): CassandraCustomConversions {
        val converters = listOf(
            IsbnReadConverter(),
            IsbnWriteConverter(),
            QuantityReadConverter(),
            QuantityWriteConverter()
        )
        return CassandraCustomConversions(converters)
    }

    @Bean
    @ConditionalOnMissingBean
    fun mongoCustomConversions(): MongoCustomConversions {
        val converters = listOf(
            IsbnReadConverter(),
            IsbnWriteConverter(),
            QuantityReadConverter(),
            QuantityWriteConverter()
        )
        return MongoCustomConversions(converters)
    }
}

// file-private — not visible outside this file
@ReadingConverter
private class IsbnReadConverter : Converter<String, Isbn> {
    override fun convert(source: String): Isbn = Isbn.parse(source)
}

@WritingConverter
private class IsbnWriteConverter : Converter<Isbn, String> {
    override fun convert(source: Isbn): String = source.value
}

// ... one pair per domain-primitive
----
====

When Spring Boot is present, each `CustomConversions` bean is annotated with `@ConditionalOnMissingBean`
so that it can be replaced by a custom configuration when needed.
Spring Boot auto-configuration will otherwise pick it up automatically — no additional setup is required.

NOTE: The configuration class is only generated when a supported store module (`spring-data-cassandra`
or `spring-data-mongodb`) is on the classpath.
Having only `spring-data-commons` present is not sufficient.

[[user-supplied-converters]]
== User-supplied Converters

The generator emits `Converter<WrappedType, DomainType>` pairs. For an `OrderDate` wrapping
`java.time.LocalDate` this means `Converter<LocalDate, OrderDate>` and `Converter<OrderDate, LocalDate>` —
correct for Cassandra (CQL has a native `date` type), but insufficient for MongoDB: BSON has no
`LocalDate` and the driver round-trips dates through `java.util.Date`. Spring Data MongoDB does not chain
converters during property population, so without a direct `Date ↔ OrderDate` pair the read path fails
with `ConverterNotFoundException`. Bridging `LocalDate ↔ Date` requires a `ZoneId` — an application
decision the generator cannot make on the user's behalf.

The two options below accept a comma-separated list of `Converter` FQNs and append them to the relevant
generated registration. Each FQN is validated at compile time:

* the class must exist
* implement `org.springframework.core.convert.converter.Converter`
* be accessible from the package where `LazyvalSpringDataConfiguration` is written
* declare a no-arg constructor with at least the same visibility
* be annotated with either `@ReadingConverter` or `@WritingConverter`.

The build fails with one error per offending FQN. The annotation is required rather than inferred from
generics — Spring Data's reflection-based fallback is not guaranteed under AOT compilation, and the
explicit annotation removes that ambiguity.

Accessibility covers more than `public`:

* Java: package-private is fine when the converter lives in the same package as the generated
  configuration.
* Kotlin: `internal` is fine when the converter is declared in the current compilation module;
  `JAVA_PACKAGE` follows the Java same-package rule.

This lets users co-locate converters with the generated configuration and keep them out of the
module's public API.

=== Worked example: `OrderDate ↔ Date` for MongoDB

Supply the converter pair with an explicit zone choice:

[tabs]
====
Java::
+
[source,java]
----
@ReadingConverter
public class DateToOrderDateConverter implements Converter<Date, OrderDate> {
    public DateToOrderDateConverter() {}

    @Override
    public OrderDate convert(Date source) {
        return new OrderDate(source.toInstant().atZone(ZoneOffset.UTC).toLocalDate());
    }
}

@WritingConverter
public class OrderDateToDateConverter implements Converter<OrderDate, Date> {
    public OrderDateToDateConverter() {}

    @Override
    public Date convert(OrderDate source) {
        return Date.from(source.value().atStartOfDay(ZoneOffset.UTC).toInstant());
    }
}
----

Kotlin::
+
[source,kotlin]
----
@ReadingConverter
class DateToOrderDateConverter : Converter<Date, OrderDate> {
    override fun convert(source: Date): OrderDate =
        OrderDate(source.toInstant().atZone(ZoneOffset.UTC).toLocalDate())
}

@WritingConverter
class OrderDateToDateConverter : Converter<OrderDate, Date> {
    override fun convert(source: OrderDate): Date =
        Date.from(source.value.atStartOfDay(ZoneOffset.UTC).toInstant())
}
----
====

Register via the processor option:

[tabs]
====
Maven (Java APT)::
+
[source,xml]
----
<compilerArg>-Alazyval.spring_data.mongo.converters=com.example.DateToOrderDateConverter,com.example.OrderDateToDateConverter</compilerArg>
----

Maven (KSP)::
+
[source,xml]
----
<apOptions>
    <lazyval.spring_data.mongo.converters>
        com.example.DateToOrderDateConverter,com.example.OrderDateToDateConverter
    </lazyval.spring_data.mongo.converters>
</apOptions>
----
====

User entries are appended after the generated ones in `mongoCustomConversions()`. `CustomConversions`
applies last-wins semantics to `(source, target)` pairs, so a user converter whose generics overlap a
generated one replaces it.

== Nullable Factory Methods (Kotlin)

When a factory method in a Kotlin domain-primitive has a nullable return type, the generated
`ReadConverter` reflects this by returning a nullable type as well.

[source,kotlin]
----
@LazyVal
class NullableQuantity private constructor(val value: Int) {
    companion object {
        fun ofNullable(value: Int?): NullableQuantity? = value?.let { NullableQuantity(it) }
    }
}
----

generates:

[source,kotlin]
----
@ReadingConverter
private class NullableQuantityReadConverter : Converter<Int, NullableQuantity?> {
  override fun convert(source: Int): NullableQuantity? = NullableQuantity.ofNullable(source)
}
----

NOTE: Spring Data's `Converter` interface declares a nullable return type (`@Nullable T convert(S source)`),
so returning `null` from a converter is a valid contract.
When `null` is returned, Spring Data propagates it to the target property — the mapping will succeed and
the property will be `null`.
This means the property holding the domain-primitive must itself be declared nullable at the call site
(`val quantity: NullableQuantity?`), otherwise a `NullPointerException` will occur at runtime.

This behaviour does not apply to the Java generator because Java's type system does not enforce
nullability at compile time.
If a Java factory method can return `null`, the generated converter will propagate it silently.

== Notes

=== Recommendation: disable default Cassandra generator

As the DataStax Java driver is pulled in transitively by `spring-boot-starter-data-cassandra`, Lazyvals `cassandra`
generator activates as well as each generator is unaware of any other at the moment. This will cause the generation of
additional Cassandra Codecs which won't interfere with Spring-Data, but they are not necessary.

Lazyval will emit a warning to give users the upper hand which generator should be disabled or not.
In general you want to set `lazyval.generators.disable=cassandra`.

=== Jackson 2 conflict with Spring Boot Cassandra

WARNING: The DataStax Java driver (`cassandra-driver-core`), pulled in transitively by
`spring-boot-starter-data-cassandra`, declares a runtime dependency on Jackson 2.
This causes the Lazyval `jackson-2` generator to activate automatically, even if you did not intend to use it.

To avoid generating unwanted Jackson 2 serialisers, choose one of the following options:

*Option 1 — disable the `jackson-2` generator explicitly:*

[source,xml,subs="attributes"]
----
<compilerArg>-Alazyval.generators.disable=jackson-2</compilerArg>
----

*Option 2 — replace the DataStax driver with its shaded variant,*
which relocates Jackson 2 to an internal package and therefore does not expose it on your classpath:

[source,xml]
----
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-cassandra</artifactId>
    <exclusions>
        <exclusion>
            <groupId>com.datastax.oss</groupId>
            <artifactId>java-driver-core</artifactId>
        </exclusion>
    </exclusions>
</dependency>
<dependency>
    <groupId>com.datastax.oss</groupId>
    <artifactId>java-driver-core-shaded</artifactId>
</dependency>
----
