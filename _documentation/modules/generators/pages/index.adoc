= Generators

Each Lazyval generator targets one integration concern — persistence, serialization, mapping, validation —
and emits the boilerplate that would otherwise need to be hand-written for every domain-primitive.

[cols="1,3"]
|===
|Generator |Purpose

|xref:beanvalidation.adoc[Bean Validation]
|`ValueExtractor` implementations so standard Jakarta validators (`@Pattern`, `@Min`, `@Past`, …) work
directly on domain-primitive fields.

|xref:cassandra.adoc[Cassandra]
|DataStax `MappingCodec` implementations for the native Java driver. For Spring Data Cassandra projects,
prefer xref:spring-data.adoc[Spring Data] instead.

|xref:jackson.adoc[Jackson 2 & 3]
|A `Module` (Jackson 2) or `JacksonModule` (Jackson 3) registering serializers and deserializers.

|xref:jpa.adoc[JPA]
|`AttributeConverter` per domain-primitive, picked up automatically by your persistence provider.

|xref:jsonb.adoc[JSON-B]
|`JsonbAdapter` implementations bundled into a `LazyvalJsonbAdapters` class with a ready-to-use `JsonbConfig`.

|xref:mapstruct.adoc[MapStruct]
|A `LazyvalMapper` interface usable as a shared configuration in other mappers.

|xref:mongodb.adoc[MongoDB]
|Native MongoDB driver `Codec` implementations bundled into a `LazyvalMongoCodecs` `CodecProvider`.
For Spring Data MongoDB projects, prefer xref:spring-data.adoc[Spring Data] instead.

|xref:spring-data.adoc[Spring Data]
|A `@Configuration` class that registers store-specific `CustomConversions` for Cassandra, MongoDB, JDBC, and R2DBC.

|===
